# Отчёт: Симуляция фокус-группы (Трек A - homo silicus)

**Тема:** Гибридные автомобили  
**Модель:** DeepSeek v4 flash

---

## 1. Задача и данные

### Гипотеза
LLM-агенты могут реалистично симулировать поведение фокус-группы для предварительного качественного исследования потребительского восприятия продукта. Синтетические персоны с различными демографическими характеристиками способны генерировать содержательные обсуждения, которые можно анализировать стандартными техниками извлечения информации.

### Сценарий
Симуляция фокус-группы на тему **«Гибридные автомобили»** - 6 синтетических персон обсуждают свои предпочтения, опасения и ожидания под руководством LLM-модератора. Дискуссия состоит из 4 раундов:
1. **Знакомство** - участники представляются, рассказывают о своём опыте с автомобилями
2. **Ассоциации** - что участники знают о гибридах, первые впечатления
3. **Плюсы и минусы** - обсуждение цены, экологии, надёжности, технологии
4. **Итоги и выводы** - свободное обсуждение, рекомендации

### Данные
- **6 синтетических демографических профилей:** разный возраст (22–68 лет), пол, профессия, доход (low/middle/high), место жительства (city/suburb/rural), опыт с авто, отношение к гибридам (positive/neutral/negative/undecided)
- **Персоны не привязаны к реальным данным** - чисто синтетические, что является явным ограничением (оговорка для трека A)
- **3 варианта темы** для eval: «Гибридные автомобили», «Экономия топлива в гибридах», «Экологичность гибридов»
- **5 seed-значений** для разнообразия генерации персон: [42, 73, 101, 204, 307]

## 2. Система

### Архитектура пайплайна

```
1. Синтетические персоны - LLM генерирует 6 демографических профилей
   ↓
2. Мультиагент: модератор + 6 персон → дискуссия 4 раунда 
   ↓
3. IE - извлечение структурированных сущностей: мнения → {аспект, сентимент, цитата} 
   ↓
4. Аспектный анализ: группировка мнений по темам 
   ↓
5. Map-Reduce: суммаризация по каждому аспекту 
   ↓
6. LLM-as-Judge: оценка согласованности, подсчёт галлюцинаций
   ↓
7. Eval: 15 тестов (3 темы × 5 seed), метрики правильности и пути
```

### Схема пути данных (5 строк)

```
input/personas.json → simulation.py → output/transcript.json
    → ie_extraction.py → output/entities.json
    → aspect_analysis.py → output/aspects.json
    → map_reduce.py → output/summary.json
    → judge.py → output/judge_report.json
    → eval.py → output/eval_results.csv
```

### Структурированный вывод
Все Pydantic-схемы в `schema.py`:
- `Persona` - профиль участника (с field_validator: age 18–90, name не пустое)
- `Utterance` - реплика (round 1–20)
- `Entity` - извлечённая сущность (sentiment: positive/neutral/negative)
- `AspectGroup`, `AspectAnalysis` - группы аспектов
- `AspectSummary`, `FocusGroupReport` - итоговый отчёт
- `JudgeEvaluation` - оценка judge (score 1–5, field_validator на каждый)
- `EvalCase` - один тестовый случай

### Проверка галлюцинаций
LLM-as-Judge сверяет каждый вывод итогового отчёта с транскриптом, подсчитывает ghost-цитаты и выдуманные факты. Результат: число галлюцинаций + примеры.

- **15 тестов:** 3 темы × 5 seed-значений

  - `hallucination_count <= 2` И
  - `transcript_grounding_score >= 3`
- **Метрики правильности:** exact match через LLM-as-Judge

## 4. Диагностика и границы

### Пример 1: Галлюцинация по аспекту «обслуживание»
- **Тест:** 15 (Экологичность гибридов, seed=307)
- **Вход:** Ольга Петрова говорит о проблемах с ремонтом гибридов в целом
- **Искажение:** В отчёте указано «неудобство для фермеров», хотя персона не упоминала фермеров
- **Цитата из judge:** *«В отчёте по аспекту 'обслуживание' указано 'неудобство для фермеров', но в транскрипте Ольга Петрова говорит только о проблемах с ремонтом в целом»*
- **Тип:** Ghost-цитата (LLM достроила конкретную группу, которой не было в транскрипте)

### Пример 2: Преувеличение консенсуса по аспекту «дизайн»
- **Тест:** 1 (Гибридные автомобили, seed=42)
- **Вход:** В транскрипте нет ни одной реплики о дизайне гибридов
- **Искажение:** Отчёт утверждает «участники единодушны в восприятии дизайна как символа современного стиля»
- **Тип:** Выдуманный аспект (модель достроила обсуждение, которого не было)

### Пример 3: Ошибка модератора - обращение к несуществующей персоне
- **Тест:** 1 (Гибридные автомобили, seed=42)
- **Вход:** Модератор обращается к «Анне»
- **Искажение:** Среди 6 участников нет персоны с таким именем
- **Тип:** Контекстная ошибка (модератор «забыл» список участников)

### Пример 4: Битый JSON от LLM (FAIL тест 10)
- **Причина:** LLM вернула некорректный JSON в шаге Map-Reduce
- **Симптом:** `Expecting ',' delimiter: line 88 column 34 (char 4403)`
- **Исправление:** Добавлен fallback-парсинг через regex и возврат пустого результата при ошибке
- **Статус:** Редкая ситуация, штатно обрабатывается

### Где система ломается (границы применимости)

1. **Среднестатистичность персон** - LLM склонна генерировать среднестатистические профили (городские жители, средний класс). Сложнее получить маргинальные группы (бездомные, люди с инвалидностью, экстремально низкий доход)

2. **Чувствительность к промпту** - формулировка вопроса модератора сильно влияет на глубину ответов. При небрежном промпте персоны дают поверхностные ответы

3. **Монокультура одной модели** - все 6 персон и модератор - одна и та же модель DeepSeek, что снижает разнообразность мнений. Разные персоны по сути - вариации одной и той же LLM

4. **Ограниченность выборки** - DeepSeek воспроизводит популярные точки зрения из обучения (экологичность, экономия топлива), а не генерирует уникальные перспективы

5. **RLHF-сглаживание** - модель избегает крайне негативных или конфликтных высказываний, что делает дискуссию «вежливее» реальной

6. **Отсутствие реальных данных** - персоны не калиброваны по реальным опросам. Результаты нельзя экстраполировать на реальные классы

## 5. Выводы

### Ответ на гипотезу
Симуляция фокус-группы через LLM-агентов **возможна и даёт качественные результаты**, но требует **осторожной интерпретации**. Средняя согласованность персон 4.1/5 подтверждает, что модель способна придерживаться заданных ролей. Однако наличие галлюцинаций (в среднем 1.0/тест) и склонность к преувеличениям (overgeneralization) требуют ручной валидации выводов.

### Что работает хорошо
- **Генерация персон** - 6 различных профилей с разным отношением к гибридам (от восторга до скепсиса)
- **Мультиагентная симуляция** - модератор успешно ведёт дискуссию по 4 раундам, вовлекает всех участников
- **IE - извлечение сущностей** - корректно извлекает мнения с аспектами и сентиментом (14–20 сущностей на тест)
- **Аспектный анализ** - группирует мнения по 6–8 темам (цена, экология, надёжность, технология, комфорт, статус)
- **Map-Reduce** - даёт связные резюме по каждому аспекту с определением консенсуса
- **LLM-as-Judge** - эффективно выявляет галлюцинации и оценивает качество

### Что не работает
- **Парсинг JSON от LLM** - пара ответов содержали некорректный JSON. Решение: regex fallback + default values
- **Обращение к несуществующим персонам** - модератор иногда ошибается в именах. Решение: строгая типизация Utterance.persona_id

### Оговорки (трек A)
| Оговорка | Описание |
|----------|----------|
| **Монокультура одной модели** | Все персоны и модератор - DeepSeek. Разные модели дали бы более дивергентные мнения |
| **Ограниченность выборки** | Модель воспроизводит популярные точки зрения из обучения (Toyota Prius как символ гибрида, страх перед заменой батареи) |
| **RLHF-сглаживание** | Модель избегает конфликтов - реальные фокус-группы содержат больше споров и эмоций |
| **Чувствительность к промпту** | Изменение описания персоны («вспыльчивый» vs «спокойный») кардинально меняет ответы |
| **Отсутствие реальной калибровки** | Персоны не основаны на реальных опросах - результаты сугубо гипотетические |

### Что можно улучшить
1. **Калибровка по реальным данным** - использовать демографические профили из РМЭЗ или ESS для более реалистичных персон
2. **Мультимодельная архитектура** - разные персоны на разных LLM для большей дивергенции
3. **Retry-логика для JSON** - автоматический повтор запроса при битом JSON с указанием предыдущей ошибки
4. **Структурированный модератор** - задавать вопросы строго по списку участников, чтобы избежать обращения к несуществующим персонам

### Рекомендации для производителя гибридов (по результатам фокус-группы)
1. **Фокус на гарантию** - участники боятся стоимости замены батареи. Длинная гарантия (8–10 лет) - ключевой аргумент
2. **Прозрачность стоимости обслуживания** - публиковать фиксированные цены на замену батареи и ТО
3. **Образовательные материалы** - многие участники не знают о рекуперации и реальной экономии в городском цикле
4. **Сельская аудитория** - требуется развитие сервисной сети и упрощение диагностики для удалённых регионов
5. **Премиум-сегмент** - гибриды воспринимаются как «компромисс» по статусу. Необходимы модели, не уступающие в динамике и мощности традиционным авто
