| Прогон | Время | Токенов | Попаданий в кэш | Промахов |

## 2. Где модель ошибалась

### Пример 1: Искажение цитаты

К счастью, проверка ghost-цитат показала **0% искажений** — все 75 цитат дословно присутствуют в исходных отзывах. IE-промпт с требованием «ТОЧНАЯ цитата из текста отзыва (дословно, на языке оригинала)» справился отлично.

### Пример 2: Неверная категория

Не обнаружено: 97 отзывов получили аспектный анализ, все 86 оценок корректно распределены по 6 категориям. Аспект «реклама» не встретился ни разу — в отзывах на Genshin Impact действительно нет рекламы внутри приложения, что корректно отражено моделью.

### Пример 3: Действие судьи

Все 5 рекомендаций судья оценил как `supported`. Score = **1.00**. Рекомендации:
1. Оптимизировать производительность (вылеты, лаги, долгая загрузка)
2. Уменьшить размер приложения (28-40 ГБ) или сделать выборочную загрузку
3. Пересмотреть монетизацию (гача, дорогие крутки, скудные награды)
4. Добавить кнопку пропуска диалогов и кат-сцен
5. Улучшить стабильность входа, исправить ошибки верификации

## 3. Что бы изменили в production

### Оставить как есть
- **Батчевая обработка** — 100 отзывов по 10 в батче хорошо работает (10 батчей параллельно).
- **ThreadPoolExecutor** — параллельные запросы (6 воркеров) сокращают время в ~5 раз.
- **Prompt caching** — модель поддерживает persistent caching, что даёт дополнительную экономию на повторяющихся префиксах.
- **check_quotes** — эффективно ловит ghost-цитаты, работает быстро (O(n) по всем цитатам).

### Переделать
- **Heatmap** — агрегировать не по группам, а по самим аспектам (топ-3 проблемных).
- **Retry при low_score** — реализовать полноценный перезапуск REDUCE с другим промптом (score = 1.00, retry не понадобился).
- **Глубокий анализ ошибок** — т.к. ghost-цитат 0%, можно протестировать модель на синтетических данных с заведомыми ошибками, чтобы проверить robustness.

### Добавить
- **Pydantic caching** — кэшировать результаты модели на диск, чтобы не перезапускать весь пайплайн.
- **Ручная валидация** — выборочная проверка 10-20% результатов человеком.
- **A/B тестирование** — сравнить две модели (дешёвая vs дорогая) на одном датасете.
- **Autodiscovery** — динамический список аспектов вместо фиксированного (для выявления неочевидных тем).
- **Детекция перевода** — часть отзывов явно машинный перевод, что может влиять на качество извлечения.
