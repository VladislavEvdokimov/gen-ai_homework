# Выводы по генерации заявок на курсы ДПО

## Перекосы и борьба с ними

Основная проблема LLM-генерации — mode collapse: модель «залипает» на одних и тех же значениях (возраст 34, стаж 10, курс «Управление проектами», район «Октябрьский»). Для борьбы с этим мы применили **двухмерную стратификацию**: города (10 × 5 = 50), возраст (25 значений от 23 до 65, по 2 каждого) и специальности (10 × 5 = 50) задаются принудительно вне LLM. Промпт усилен явными запретами (без age=34, без стаж=10, без «Управления проектами», без «Октябрьского») и few-shot примерами с редкими фамилиями. Результат: специальности — идеально (ровно по 5 каждой), возраст — 25 уникальных значений, все 8 курсов представлены. Однако остаётся bias: курс «Финансовый анализ» доминирует (28%), модель переключилась с «Октябрьского» на «Кировский» район (9/50), имена всё ещё повторяются (42/50 уникальных). Для полного устранения нужна стратификация курсов и пул районов для каждого города.

## Валидатор

В `model_validator(mode="after")` реализованы две межполевые проверки: возраст ≥ минимального для специальности (врач: 24 года, остальные: 22) и стаж ≤ возраст − 18. **За 50 заявок валидатор ни разу не сработал** — seed-параметры в генераторе подобраны корректно, и модель не выходила за рамки. Валидатор служит страховкой: он не нужен при правильных seed-параметрах, но поймает аномалию при сбое в цепочке генерации или если модель проигнорирует промпт.
