## 2. Параллельность

**Реализация:**
- `_topological_sort` переименована в `_topological_levels`, которая возвращает `list[list[SubQuestion]]` — список уровней, где внутри уровня нет зависимостей.
- `execute_level(level, prev_answers)` запускает все подвопросы уровня через `ThreadPoolExecutor`.

**Замеры:**

| Вопрос | Подвопросы | Уровни | Послед., с | Паралл., с | Ускорение |
|--------|-----------|-------|-----------|-----------|----------|
| Q1: рост USD (2 подвопроса, зависимость) | 3 | 2 | 14.48 | 9.79 | 1.48× |
| Q5: курсы USD/EUR/CNY (3 независимых) | 4 | 2 | 18.10 | 8.50 | 2.13× |

**Вывод:** Ускорение прямо пропорционально количеству независимых подвопросов на уровне. Для Q1 (цепочка зависимостей) ускорение 1.48×. Для Q5 (3 независимых) — 2.13× ускорение за счёт ThreadPoolExecutor.

## 3. Замер критики

Прогон 5 битых кейсов × 10 раз при T=0.0 и T=0.7.

| Битый кейс | T=0.0, ложных принятий | T=0.7, ложных принятий |
|------------|----------------------|----------------------|
| арифметика без calculate | 0/10 | 0/10 |
| выдуманное число | 10/10 | 10/10 |
| несогласованные данные | 0/10 | 0/10 |
| ответ с ошибкой | 0/10 | 0/10 |
| план не покрывает вопрос | 0/10 | 0/10 |

**Гипотеза «шум лечит зеркальное соглашение» НЕ ПОДТВЕРЖДЕНА:** При T=0.0 и T=0.7 результаты ложных принятий идентичны для всех 5 кейсов. Единственный кейс, где критик ошибся — «выдуманное число» (10/10 ложных принятий на обеих температурах) — не может быть отловлен критиком в принципе, так как у критика нет доступа к реальным данным для верификации чисел. Остальные 4 кейса критик ловит стабильно при любой температуре (0/10).

## 5. Вывод

**Когда PWC оправдан:**
- Задача требует декомпозиции на несколько вызовов инструментов (курсы, ставки, инфляция).
- Есть арифметика — PWC гарантированно добавит `calculate`.
- Есть независимые подвопросы — параллельность даёт ускорение.
- Планировщик может выдумать инструмент — валидатор ловит и исправляет.

**Когда лучше остаться с одиночным агентом:**
- Простые вопросы на 1-2 шага (один `get_fx_rate` или `get_key_rate`) — накладные расходы PWC не оправданы.
- Вопросы, требующие цепочки из многих шагов (50 get_inflation для Q3) — PWC не справляется.
- Система не терпит задержек — каждый дополнительный LLM-вызов добавляет секунды.

**Общий вывод:** PWC с валидатором и параллельностью решает проблемы галлюцинаций и арифметических ошибок, но имеет смысл для вопросов средней сложности (3-7 шагов). Для простых вопросов выгоднее одиночный агент, для сверхсложных — PWC тоже не панацея, нужны другие подходы.
